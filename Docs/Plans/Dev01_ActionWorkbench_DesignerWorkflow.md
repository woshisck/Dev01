# Dev01 动作工作台：策划与美术操作方案

日期：2026-09-08  
状态：界面与制作流程提案，尚未实现。本文不修改动作规则、冲刺、Tag、资产或运行时代码。

## 1. 你日常只需要做什么

建议做一个 `Designer → 动作工作台`，让你管理“动作是什么、动作之间怎么衔接、动画什么时候允许操作”，而不是管理 Tag 字符串。

日常工作压缩为：**选择动作 → 选择规则预设 → 拖动画时间窗口 → 预览为什么允许/不允许 → 校验并保存。**

新建一招普通攻击，应当像新建一行物品配置一样：填名称、选武器、拖入动画、选“普通近战”预设即可；不需要打开 Gameplay Tags 设置，不需要手写 `BlockTags`，也不需要复制别人的 GA 再猜它藏了哪些限制。

这不是“把所有 Tag 换成另一套难记的 ID”。中文名称、缩略图和动作资产是操作对象；稳定内部 ID、Tag 映射、注册和生命周期接入由工具与程序维护，并收在只读高级信息中。

## 2. 一个入口，四个页面

| 页面 | 你处理的问题 | 常用操作 |
| --- | --- | --- |
| 动作目录 | 这把武器有哪些动作，用哪段动画和哪套规则？ | 新建、复制为新动作、筛选角色/武器、批量选预设、定位资产 |
| 衔接规则 | 正在普攻时，按战技会怎样？ | 点击有向矩阵格子，选“禁止/排队/共存/打断后执行”，查看条件 |
| 动画窗口 | 第几帧能移动、能转向、能接下一招？ | 在动画预览上拖区间、逐帧播放、比较修改前后 |
| 运行诊断 | 我现在为什么不能移动或放技能？ | 选中 PIE 角色，查看阻止来源、剩余条件、跳转规则 |

顶部始终显示：`当前策略版本 / 草稿或生效版 / 校验结果 / 未保存修改 / 受影响动作数量`。基础/高级视图是同一份数据的不同展示，不是两套会相互覆盖的表。

第一版可以复用当前 Slate 工作台风格；不是要求重做全项目编辑器。

## 3. 动作目录：像制作表，不像程序配置表

建议的默认列如下。表中内容是示例，不表示这些示例已被写入项目。

| 显示名称 | 动作类型 | 适用范围 | 动画 | 衔接预设 | 操作窗口 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 双手剑·普攻第 1 段 | 普攻 | 玩家 / 双手剑 | 拖入蒙太奇 | 普通近战 | 点击编辑时间轴 | 草稿 |
| 双手剑·旋风斩 | 战技 | 玩家 / 双手剑 | 拖入蒙太奇 | 持续近战 | 点击编辑时间轴 | 草稿 |
| 玩家·冲刺 | 冲刺 | 玩家 / 默认 | 已有蒙太奇 | 现有规则 | 查看现有窗口 | 暂缓修改 |
| Guard·前劈 | 敌人攻击 | Guard | 已有蒙太奇 | 敌人普通攻击 | 点击编辑时间轴 | 草稿 |

设计要求：

- “动作类型”只提供项目已支持的选项：普攻、主动技能、战技、冲刺，以及程序已接入的敌人动作/反应类型。不能靠填写任意新名称自动发明新运行时行为。
- 第 1 段、第 2 段是动作条目的阶段/槽位，不要求策划为每个武器、皮肤、动画创建新的全局 Tag。
- `复制为新动作` 自动生成新的内部身份；`作为已有动作的动画变体` 保留动作身份，只新建变体。二者必须分开，避免复制出 ID 冲突。
- 改中文名称不改身份，不改 Tag，不破坏存档或引用；删除有引用的动作必须先给出引用列表与替换选择。
- 自动从批准的武器、主动技能、战技资产位置建立目录；未接入或无法识别的能力显示“需要程序接入”，不默认为可用。
- 每行可展开“正在使用的规则从哪里来”：框架默认 → 当前预设 → 明确的例外覆盖。不能隐藏资产或蓝图里的旧规则。

### 新建动作向导

1. 选择“从已有模板创建”，例如普通近战、持续技能、敌人攻击。
2. 输入中文名，选择适用角色/武器，拖入动画。
3. 选择一个已审核预设；工具提供默认窗口候选并要求预览确认，不自动猜测动画命中帧。
4. 工具完成受支持资产的创建/关联，显示将修改哪些文件。
5. 点击“校验草稿”，解决缺动画、窗口越界、规则遗漏等问题后保存。

普通内容制作不再找程序登记一次。**新增机制**，例如程序尚不支持的抓取、骑乘、多人合体动作，仍需程序实现一次模板和接入契约；表格不能替代新玩法代码。

## 4. 衔接规则：不要让策划手填两堆 Block/Cancel Tag

矩阵的方向固定：**行是新请求，列是正在执行的动作**。旁边同步显示一句自然语言，避免读反。

| 你选择的结果 | 界面解释 | 注意事项 |
| --- | --- | --- |
| 禁止 | 当前动作继续，新动作不启动 | 不取消当前动作 |
| 排队 | 暂存输入，进入合法窗口后再判断 | 需填写等待时限；过期丢弃；仍检查冷却等条件 |
| 共存 | 两个动作可同时存在 | 同一身体动画槽/资源冲突时不能假装共存 |
| 打断后执行 | 请求结束指定当前动作，再启动新动作 | 必须允许取消并满足窗口；激活失败不等于旧动作能倒放恢复 |

“继承预设”是配置来源，不是第五种运行结果；空白显示红色“尚未定义”，绝不暗示允许。

### 你此前需求会怎样显示

以下全部保存为**未启用的需求草稿**，不改变现在已暂缓的冲刺问题。

| 新请求 | 当前动作 | 草稿结果 | 自然语言说明 |
| --- | --- | --- | --- |
| 普攻 | 冲刺 | 禁止 | 冲刺中按普攻，不中断冲刺 |
| 冲刺 | 普攻 | 打断后执行 | 冲刺请求允许结束普攻；具体阶段另行确认 |
| 战技 | 普攻 | 打断后执行 | 战技请求允许结束普攻；具体阶段另行确认 |
| 战技 | 冲刺 | 禁止 | 战技不打断冲刺 |
| 冲刺 | 战技 | 待确认 | 前四条不能推出这一条，需要单独决定 |

点击格子只编辑“适用阶段、结果、等待时限、例外说明”，底层如何把规则映射到能力实例、OwnedTag 和取消调用不向策划暴露。

### 白名单用“这条限制允许谁”表达

建议名称为“允许例外”，放在具体限制卡片下，例如：

> 对话期间：限制战斗输入、角色移动、敌人决策。允许例外：对话确认、对话取消、镜头操作。

选项是中文动作/操作组，不是 Tag 文本。界面必须提示：**这里的允许只豁免对话这一项限制；角色如果同时死亡，仍不能攻击。** 不提供“把这个动作加入全局白名单，从此无视所有锁”的按钮。

死亡、场景切换等框架硬性安全约束展示为锁定行；不能被普通美术预设解除。更改这类规则必须进入程序审查范围。

## 5. 预设减少工作量，例外必须看得见

预设用于复用“整套已审核规则”，不是一个神奇的 Priority 数字。初始建议由程序和策划共同整理：普通近战、持续技能、敌人普通攻击、受击反应、对话控制；先从实际行为导入，不能把示例当成既定玩法。

对于一把新武器：选普通近战预设后，只配置不同的动画和窗口；需要特例时点“增加例外”，并显示金色标记及一句变更说明。

修改共享预设前，工作台列出使用它的所有武器/角色，并区分：跟随预设、存在覆盖、不受此次修改影响。支持“只为选中动作建立派生预设”，避免改一个动作把全角色行为改掉。

作用域不无限嵌套：推荐“项目默认 → 命名预设 → 动作明确覆盖”三层；同层矛盾直接报错，不隐藏一套难以理解的优先级。

## 6. 动画窗口：美术编辑条带，不写 Tag Notify

时间轴以实际蒙太奇、段落、播放速率为依据，显示帧数与秒数，提供以下可读轨道：

| 轨道 | 编辑含义 |
| --- | --- |
| 动作阶段 | 前摇、出招、收招、结束；为规则提供阶段，不自动更改伤害结算 |
| 移动输入 | 何时允许玩家走动；与动画自身位移分开 |
| 朝向调整 | 何时允许跟随输入/目标转向，最大转向速度由预设提供 |
| 动作衔接 | 何时允许普攻/战技等请求进入候选，具体许可仍由矩阵决定 |
| 动画位移 | 是否保留动作自身 Root Motion；普通“禁止走动”不顺手清空它 |
| 表现参考 | 命中、声音、特效等现有事件只读叠加，用来对齐时机；需要编辑时跳转其真实所属资产 |

工具内部创建合法的窗口记录/通知，绑定当前动作实例并自动清理；美术无需记忆 `CanCombo` 或 `ANS_AddGameplayTag`。

修改前先标出窗口来源：现有蒙太奇通知、MontageConfig 条目还是提案的新策略窗口。一个窗口只允许一个可写权威来源；导入后需要迁移预览，不能让新条带和旧 Notify 同时执行两遍。

更换动画后不悄悄按原帧号套用：重新检查时长、播放速率、段落和命中位置；越界、缺失结束和零长度非法窗口都应提示。若采用归一化重映射，必须预览并由作者确认。

## 7. “为什么被锁”要能给制作人员看懂

选择运行中的角色，面板应首先显示人话，而不是整屏 Tag：

> 最近请求：战技“旋风斩”  
> 结果：未执行  
> 原因：当前冲刺禁止战技插入  
> 来源：玩家冲刺预设 → 衔接规则第 4 条  
> 同时存在：对话限制（尚未结束）  
> 下一次可执行条件：冲刺结束、对话结束，并且技能冷却完成

另一个常见问题应显示：

> 不能走动：受击动作仍持有限制；已持续 1.8 秒；正常释放条件为“该动作结束”。

可点击“定位规则”“定位动画窗口”“复制诊断报告”“比较前后两次请求”。预计结束时间不确定时显示条件，不编造倒计时。底部展开才展示 Tag、GA、所有者和内部句柄供程序定位。

观察模式必须分别显示“真实旧系统结果”和“新方案模拟结果”，不能把模拟允许误当作已经执行。初期未接入的限制明确标为“旧入口，来源尚未归属”。

不向正常制作流程提供“一键清空全部锁”。开发环境若提供应急解除，只能定位到具体来源，并显著说明它会改变本次运行；不能把解除按钮当成修复问题。

## 8. 表格可以有，但不能变成第二份真相

推荐 **UE 工作台为主，表格导入/导出为批量入口**。

- 全局策略资产保存动作许可、预设、矩阵和限制规则；动作目录索引已有动作资产，武器和技能资产保留动画/数值/GA 等原有职责。
- 时间轴窗口写回其明确所属的动作配置，不复制成一张互相漂移的 Excel 窗口表。
- 导出包含只读稳定 ID、中文名、规则版本、来源资产和可编辑业务列；稳定 ID 不根据中文名或行号生成。
- 导入先做预览，明确新增/修改/缺失引用/冲突行，不直接覆盖所有资产；表格中的删除行不自动删除动作。
- 旧版本导入遇到其他人已改过的单元格必须提示冲突，不能最后保存者静默覆盖。
- Excel 中用筛选和下拉；UE 中用资产选择器和中文动作搜索。普通用户不编辑 Tag 列。
- 二进制动作/策略资产属于 P4；评审用的文本快照可以按批准白名单进入 GitHub。不要将完整 Content 资产同步到 GitHub。

逻辑上“一个管理入口”不等于“每次修改都锁住一个巨大 uasset”。策略规则集中、现有动作/动画资产按职责分开，工作台显示每次涉及的文件和 P4 打开者，避免两名美术同时修改同一资产。

## 9. Tag 自动管理与现有项目的兼容边界

当前实际字典是 `Character.State.Skill.Attack.Combo1` 至 `.Combo4`，不是 `Character.State.Skill.Attack.1` 至 `.4`；工作台统一显示“普攻·第 1 段”等中文名字，让内容作者不必处理这个差异。

如果旧资产确实保存了 `.Attack.1`，先列入兼容扫描并显示“待确认旧名称”，再由程序确认明确映射并用项目正式迁移工具处理。本文没有新增 redirect，也没有断言 `.Attack.1` 目前已经能被正确解析。

职责约定：

- 核心动作/状态 Tag 由程序统一声明和注册到所属字典；普通新动画、新武器、新动作变体不自动增加一枚全局 Tag。
- 编辑器对已支持模板自动填入既有正式映射和资产关联；新类型没有适配器就不能通过发布检查。
- 高级人员可查看底层映射和兼容来源，但策划改显示名不会重命名 Tag。
- 既有 GAS 成本、冷却、目标有效性继续检查；表格中的“允许”不能绕开它们。
- 战技继续激活当前装备的精确能力实例，不因中文目录和统一规则改回按大类 Tag 随便匹配。

## 10. 保存、测试与发布体验

“保存草稿”与“启用规则”必须分开。工作台的“校验/导出”不是自动向 P4 或 GitHub 提交。

建议每次修改按以下顺序完成：

1. 保存前显示文件清单与当前占用情况；支持撤销/重做，保护用户未保存的其他资产。
2. 静态校验：动作重复、未知模板、引用缺失、窗口越界、规则冲突和未定义矩阵格。
3. 策略沙盘：指定“当前动作 + 阶段 + 输入 + 附加限制”，立即显示预计裁决；它不是完整动画/游戏测试的替代品。
4. 隔离 PIE 试验：默认不写正式玩家存档；录制有限时长的输入/状态/锁诊断，检查真实表现和所有失败出口。
5. 输出本次差异和受影响用例，由审批者将草稿设为候选版本；冲刺待定草稿保持禁用。
6. 经项目编译、回归、发布验收后生效。保留上一版规则和资产集合，支持受控回滚，不在技能执行一半时随意热切换。

没有框架能承诺“永远没有错误”。能要求的是：缺配置不能悄悄上线、错误能指出来源、动作结束不会遗留自身限制、修改有差异和回滚证据。

## 11. 第一版验收：以制作人员是否真的省事为准

第一版先交付“动作目录 + 预设/矩阵 + 只读为什么被阻止”，再完善动画条带与批量表格。不要先花时间做复杂的无限节点图。

验收任务：

- 策划不打开 Tag 设置、不编辑 C++，完成一个受支持模板下的新动作配置。
- 动画人员能用时间轴调整一个移动/转向窗口，并看到真正受影响的动画段。
- 两个反向矩阵格能表达不同规则，不会把“冲刺打断攻击”错误等同于“攻击也能打断冲刺”。
- 修改共享预设前能看到受影响武器清单；为一个动作做例外不会悄悄改变其他动作。
- 对话与受击同时限制移动时，任意一个结束仍能看见另一个来源；不靠全局白名单或手动清锁解决。
- 旧 Tag、未接入蓝图和窗口冲突能在校验页定位到具体资产，而不是运行后才猜测。
- 导入一份过期表格会报告冲突；不会覆盖同事改动或自动删除未出现的资产。
