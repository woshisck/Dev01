# 敌人编辑器使用指南

## 1. 范围

本工具把分散在敌人 BP、`EnemyData`、属性表、GAS、武器与行为树中的配置整理为一个独立策划编辑器。敌人、武器和后续关卡编辑器分别使用自己的窗口，不通过合并式多页容器切换；它们只在顶部统一归入 `Designer` 菜单，方便查找。

打开路径：

`Designer -> 敌人编辑器`

`Designer -> 武器编辑器` 仍会打开另一张独立编辑器页，不会把敌人和武器合并在同一个窗口内。

敌人编辑器不会替代现有运行时数据结构。它负责发现、创建、编辑、分类和校验 `UEnemyData`，并在当前窗口内编辑主要关联配置。

## 2. 资产隔离规则

| 分类 | 固定根目录 | 规则 |
|---|---|---|
| 正式敌人 | `/Game/Code/Enemy/Definitions` | 进入正式库并接受完整发布校验 |
| 测试敌人 | `/Game/Test/Enemy` | Dummy、木头人及程序测试敌人；不强制满足正式发布校验 |
| 旧资产 | `/Game/Docs/Data/Enemy` | 只显示为“待迁移”，不再视为正式资产目录 |
| 占位计划 | 尚未生成资产 | 显示项目已确认但还没有正式 `EnemyData` 的敌人 |

正式资产建议路径：

`/Game/Code/Enemy/Definitions/<Normal|Elite|Boss>/<EnemyId>/DA_EN_<EnemyId>`

测试资产建议路径：

`/Game/Test/Enemy/Utility/<EnemyId>/DA_TEST_EN_<EnemyId>`

点击占位条目的“创建所选占位资产”会按以上规则创建 `UEnemyData`。工具不会自动移动或覆盖旧资产，迁移必须逐项确认引用后执行。

## 3. 左侧敌人库

左侧提供四类筛选：

- 正式资产：已经位于正式目录的敌人。
- 占位计划：已确认的敌人清单中尚未建立正式资产的项目。
- 待迁移：现有但仍位于旧目录或其他非正式目录的敌人。
- 测试库：Dummy、训练木头人及其他测试敌人。

搜索同时匹配敌人 ID、中文名、英文名与资产路径。选中真实资产后按 `Ctrl+B` 可在内容浏览器中定位。

配置了 `EnemyClass` 的真实敌人条目可以从左侧按住并直接拖入关卡视口。工具会生成该敌人 BP，并自动把当前 `EnemyData` 写入角色数据组件；占位条目或缺少 `EnemyClass` 的资产会被明确拦截并提示修复要求。

## 5. 身份、分类与制作状态

`EnemyData -> Enemy|Identity` 中的字段：

| 字段 | 作用 |
|---|---|
| `EnemyId` | 稳定程序标识；保存、统计和后续引用不应依赖中文显示名 |
| `DisplayName` | 面向策划和玩家的中文显示名 |
| `EnglishName` | 英文检索和对外命名 |
| `CombatTier` | 普通、精英或 Boss |
| `ProductionStatus` | 占位、制作中、可玩、已验证 |
| `FactionTag` | 阵营；只允许 `Enemy.Faction.*` |
| `RegionTags` | 敌人可能出现的区域；只允许 `Enemy.Region.*` |
| `bTestOnly` | 是否为测试专用敌人 |

`Enemy.Faction` 和 `Enemy.Region` 根标签已经建立。具体子标签应由策划确认命名后再增加，避免程序自行创造重复语义。

## 6. 三栏界面与内嵌配置

敌人编辑器与武器编辑器采用一致的三栏阅读方向：

| 区域 | 作用 |
|---|---|
| 左侧 | 搜索、分类、选择和拖放敌人 |
| 中间 | 按页面直接编辑当前敌人的主要配置 |
| 右侧 | 持续显示错误、警告、发布要求与关联配置状态 |

中间栏页面：

| 页面 | 直接编辑的内容 |
|---|---|
| 身份与概览 | ID、中英文名、敌人级别、制作状态、阵营、区域、测试标记、难度 |
| 角色基础数据 | 移动数据表行、基础属性表行、默认动画层 |
| Ability 数据 | 选择并直接编辑 `AbilityData` 或 `GASTemplate` |
| 敌人 BP | 选择 `EnemyClass`，并直接编辑其 Class Default Object 的模型、动画、组件引用与默认参数 |
| AI 与战斗 | 行为树、武器、Buff、移动/感知/攻击调参、霸体参数 |
| 生成与奖励 | 出生特效、生成流程与敌人自己的击杀掉落 |

这些依赖仍保留各自的数据职责；编辑器只把真实对象内嵌到统一界面中，不复制数据，也不制造第二套真源。右侧的快捷按钮只切换中间页面，不会另开 BP 或 DA 编辑器。

## 7. 敌人击杀奖励与关卡奖励

两类奖励必须同时保留且相互独立：

| 奖励来源 | 配置归属 | 用途 |
|---|---|---|
| 敌人击杀掉落 | `EnemyData.bEnableKillRewards`、`EnemyData.KillRewards` | 某种敌人死亡时独立判定的掉落 |
| 房间/关卡奖励 | `RoomDataAsset.LootPool` 及现有关卡奖励流程 | 清场、房间结算或关卡目标奖励 |

`KillRewards` 每项包含：

- `Loot`：奖励类型与内容，目前可表达 Rune、Gold、Material。
- `DropChance`：该项独立掉落概率，范围 0–1。
- `MinQuantityMultiplier` / `MaxQuantityMultiplier`：基础数量的随机倍率范围。

当前阶段已完成敌人奖励的配置结构、编辑入口与合法性校验；尚未把新数组接入敌人死亡时的运行时发奖流程。正式启用前还需单独完成“死亡权威端判定、生成/入包方式、多人去重、存档与测试”，避免在编辑器验收阶段改变现有战斗奖励行为。

## 8. `DropExp` 是什么

`DropExp` 是 `UEnemyAttributeSet` 中遗留的 GAS 数值属性。当前代码只在构造函数里将它初始化为 `0`，没有找到死亡奖励流程对它的读取或发放逻辑，因此它现在不是一个有效的经验掉落系统。

本次没有删除、改名或复用 `DropExp`。新的敌人击杀奖励配置与它明确分离，避免一个未接线的旧字段同时承担金币、材料、符文或经验等多种含义。

## 9. 正式校验

右侧校验栏使用高对比字体与颜色区分：

- 红色：阻止拖放、运行或正式发布的错误。
- 橙色：需要核实或补齐的警告。
- 蓝色：制作和分类要求。
- 绿色：当前项目未发现错误或警告。

正式敌人至少检查：

- 资产位于正式根目录。
- `EnemyId` 和 `DisplayName` 已填写。
- `EnemyClass`、`GasTemplate`、`AbilityData`、`BehaviorTree`、`DefaultWeaponDefinition` 已配置。
- 启用击杀奖励时，每项概率和数量倍率合法。

测试敌人显示分类与标记，但跳过以上正式发布硬门槛。

## 10. 保存与 P4

“签出并保存”会处理当前 `EnemyData`，以及通过中间页实际编辑过或关联的 `AbilityData`、`GASTemplate` 和敌人 BP。提交前仍应人工确认：

1. `p4 opened` 中只包含本任务文件。
2. 新正式资产位于 `/Game/Code/Enemy/Definitions`。
3. 测试资产位于 `/Game/Test/Enemy`。
4. 没有把旧目录资产误标为正式资产。
5. 没有夹带关卡、角色渲染或其他人的默认 changelist 文件。

## 11. 后续阶段

敌人编辑器通过人工验收后，再实现独立的关卡编辑器窗口。关卡编辑器将管理 `RoomDataAsset`、波次、关卡目标、关卡奖励与传送关系；不会把这些职责重新塞回 `EnemyData`，也不会与敌人或武器编辑器合并成多页窗口。
