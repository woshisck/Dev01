# Hardware Mouse Cursor Setup

## Asset entry points

- Cursor config DataAsset: `/Game/UI/DA_YogCursorStyle`
- C++ type: `UYogCursorStyleDataAsset` (`Source/DevKit/Public/UI/YogCursorStyleDataAsset.h`)
- ini registration: `Config/DefaultGame.ini`, section `[/Script/DevKit.DevAssetManager]` → `CursorStyle=/Game/UI/DA_YogCursorStyle.DA_YogCursorStyle`
- Image location: `Content/Slate/Cursors/` (**loose image files**, not imported texture assets)
- Applying code: `AYogPlayerControllerBase::ApplyHardwareCursorStyle()`, runs on `BeginPlay`

## Purpose

The game uses a **hardware cursor**, drawn by the operating system, so it has no lag. This DataAsset
lets a designer pick the image for each cursor state without touching code.

## The one constraint that matters most

A hardware cursor is created by the OS from an **image file on disk**. The engine cannot pull an
image out of a `.uasset`.

| Value | Result |
| --- | --- |
| `Slate/Cursors/Pointer` | Correct — reads `Content/Slate/Cursors/Pointer.png` |
| `UI/Playtest_UI/Runes/T_Icon_Shadow_Dash` | **Fails** — only a `.uasset` lives there, no `.png` |
| `/Game/UI/Cursors/Pointer` | **Fails** — resolves to `Content//Game/UI/...`; never use a `/Game/` prefix |
| `Slate/Cursors/Pointer.png` | **Fails** — never include the file extension |

Path resolution is `Content/` + `CursorPath` + platform extension. On Windows the search order is
`.ani` → `.cur` → `.png`.

## Field reference

`CursorArt` is a map of `EYogCursorState` → `FYogCursorArt`.

| Field | Type | Meaning |
| --- | --- | --- |
| `CursorPath` | `FName` | Path relative to `Content/`, **no extension and no `/Game/` prefix**. Leave empty to keep the OS default for that state |
| `HotSpot` | `FVector2D` | The click point, **normalized 0–1**, not pixels. `(0,0)` is top-left, `(0.5,0.5)` is the image center |

## State to cursor-slot mapping

Each game state maps onto a stock engine cursor slot. The mapping is fixed in
`UYogCursorStyleDataAsset::StateToSlot()`.

| `EYogCursorState` | Engine cursor slot | Side effect |
| --- | --- | --- |
| `Default` | `EMouseCursor::Default` | The normal pointer |
| `Interact` | `EMouseCursor::Hand` | Any UMG widget with `Cursor = Hand` uses this image automatically |
| `Drag` | `EMouseCursor::GrabHandClosed` | Useful while dragging runes |
| `Invalid` | `EMouseCursor::SlashedCircle` | Useful for illegal placement |

Because the stock slots are reused, any button already set to `Cursor = Hand` picks up the
`Interact` image for free — no extra wiring needed.

## Setup steps

1. **Prepare the image.** 32x32 is recommended, 64x64 maximum. An oversized image (for example an
   818x818 rune icon) produces an enormous cursor. For high DPI, name the variants `Pointer.png`,
   `Pointer@1.25x.png`, `Pointer@2x.png` and the engine picks the right one.
2. **Put it in `Content/Slate/Cursors/`.** Copy the PNG in with the file explorer. Do **not** import
   it as a texture asset.
3. **Fill in `DA_YogCursorStyle`.** Add a `CursorArt` entry, pick the state as the key, set
   `CursorPath` to `Slate/Cursors/<your file name>`, and set `HotSpot` in normalized coordinates.
4. **Save the asset and restart PIE.** Cursors are registered during `BeginPlay`, so a fresh PIE
   session is required. Changing the ini path instead requires an editor restart.

### Using an existing texture asset as a cursor

Right-click the texture in the editor → `Asset Actions` → `Export`, save it as a PNG, scale it to
32x32, then drop it into `Content/Slate/Cursors/`. The original import path is also visible in the
texture asset's Source File info.

## Recommended example

```text
CursorArt
  Default  : CursorPath = "Slate/Cursors/Pointer"   HotSpot = (0.2, 0.2)
  Interact : CursorPath = "Slate/Cursors/Hand"      HotSpot = (0.5, 0.5)
```

The current `Pointer.png` and `Hand.png` under `Content/Slate/Cursors/` are **placeholders** copied
from the engine's Slate icons. Replace them with real art — keep the same file names and no config
change is needed.

## How to test

Start PIE, then search the Output Log for `Cursor`:

| Log line | Meaning |
| --- | --- |
| `LogInit: Loading Cursor '.../Content/Slate/Cursors/Pointer.png'.` | Loaded successfully |
| `LogInit: Error: Failed to load cursor '...'` | The engine could not find the file |
| `LogTemp: Warning: [YogCursor] Failed to load hardware cursor '...'` | This project's warning; it prints the offending path |

No `[YogCursor]` warnings means every entry registered successfully. Also move the mouse into the
viewport: the custom cursor should appear, and clicks should land on the image's visual tip. If they
land offset, `HotSpot` is wrong.

## Packaging note

Loose PNGs are not assets, so they are never cooked. `Config/DefaultGame.ini` already contains:

```ini
[/Script/UnrealEd.ProjectPackagingSettings]
+DirectoriesToAlwaysStageAsNonUFS=(Path="Slate")
```

That path is relative to `Content/`. If cursor images are placed outside `Content/Slate/`, add
another entry, otherwise the cursors work in PIE and silently disappear in a packaged build.

## Related note

`UYogCursorWidget` and the four `Cursor*Texture` fields on `DA_PlayerUIStyle` belong to the older
**software cursor** approach, where Slate repaints the cursor every frame and it visibly trails the
pointer at low framerate. That path is currently disabled and kept only because
`Content/UI/UI_MouseCursor` may derive from it. Configuring the hardware cursor does not require
touching those fields.
